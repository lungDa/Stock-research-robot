# 股海燈塔｜交易整合前安全基線

範圍：`feature/day-trader-integration`。本階段**不連接券商、不送出真實委託、不修改正式 main**。

## 現況與已確認限制

- API 使用 LINE OAuth + 個人密碼，仍保留在未設定 LINE Login 時啟用的舊式 bearer token 模式。
- `app/db.py` 使用 SQLAlchemy，持有個人清單、偏好與 JSON 文件；目前沒有正式交易用訂單、成交、持倉、風控資料表。
- `app/services/market_recommendations.py` 的多因子「買」評級屬研究推薦，**不是**可直接下單的許可。
- GitHub Actions 可用於資料更新及排名通知，不得當成即時停損或可靠的交易執行程序。
- `render.yaml` 仍宣告免費 Web Service；未驗證 SPARK SDK 的作業系統、憑證與網路需求。
- 既有密碼註冊流程包含初始密碼 `0000` 與強制更改旗標。正式交易前必須改成不可預測的一次性啟用程序，並全面停用不必要的舊式存取金鑰。
- 既有多使用者資料隔離主要透過 user key；交易帳戶必須使用強制 tenant/account 綁定及資料庫層級限制。

## 開發驗收門檻

1. 預設 **LIVE_TRADING_ENABLED=false**；任何未完成授權的路徑必須 fail-closed。
2. 模擬交易與真實交易使用不同的 adapter、憑證、資料表或清楚的環境隔離。
3. 訂單需唯一 client_order_id、重試冪等、交易所交易時段/商品資格檢查、價格與口數限制。
4. 風控需獨立於 AI，包含單筆上限、日虧損上限、總曝險、可用資金、重複委託、停損、緊急停止。
5. 每次送單前需核對券商現有委託、成交、庫存與可用資金；網路逾時不得盲目重送。
6. 交易權限與 LINE 訊息查詢權限分離；啟用實盤、變更額度、綁定券商須重新驗證。
7. API key、憑證與密碼只存於秘密管理系統；不得提交至 GitHub 或輸出至日誌。
8. 交易事件與稽核紀錄採不可任意覆寫的追加式設計；需保留交易決策時的行情時間與資料來源。
9. 正式交易前必須通過單元、整合、故障注入、券商沙盒/UAT、人工核准及小額分階段驗收。
