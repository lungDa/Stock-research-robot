# 股海燈塔重構階段紀錄

## 已完成

- PostgreSQL 連線池啟用閒置連線優先回收，最多五條連線。連線建立與等待池中連線各設五秒，保留借出前的連線檢查。既有連線與交易失敗後仍由呼叫端決定是否可重試。
- 快取文件改用原子 upsert。台股備援行情與成功狀態使用同一交易發布。台股月份快取每檔以一條 SQL 讀取四個月。
- Streamlit 定期探測流程改為驗證 Render 的資料庫就緒狀態。健康探測保留原有頻率。
- 移除七份位於儲存庫根目錄的工作流程副本。各副本在修改前與 `.github/workflows/` 內的對應檔案完全相同。
- 加入逆勢研究計算函式，提供五個基準權重、風險分級、可用時間對齊與下行統計。基礎回測依輸入訊號在下一個交易時段進場，支援 10、20、30 個交易日持有期間。這些函式目前只接受呼叫端提供的歷史資料與訊號。

- 市場資料串流會檢查陣列分隔符號及結尾，避免將格式錯誤的行情認定為完整市場資料。
- 台股快取內容無變動時省略寫入。現有個人規則排名每批讀取最多七檔的資料，原為五檔。
- 逆勢核心新增五個基準與綜合排名。排名只放寬零檔符合的門檻，最多輸出十檔。上游仍須提供可比較的基準分數與可用性判斷。

- 排名排程超出發送窗口時回報跳過，提前結束而不讀取資料庫或發送訊息。
- 基本面來源遇到連線、讀取逾時或伺服器錯誤，保留上次成功的資料與狀態，將該來源的下一次嘗試從一天後提前至一小時後。

## 測試與效能

| 驗證 | 基準 | 本階段 |
| --- | ---: | ---: |
| Python 3.12 完整回歸 | 773 通過 | 787 通過 |
| 每次讀取四份快取文件的 SQL 查詢數 | 4 | 1 |
| 中位延遲 | 0.984 ms | 0.368 ms |
| P95 延遲 | 1.461 ms | 0.540 ms |

延遲來自本機 SQLite 記憶體資料庫，每個版本各執行 1,000 次讀取。從開發環境向正式 Render 發送的兩次探測各逾時 12 秒，未取得 HTTP 回應，無法據此判斷正式服務狀態。正式服務延遲、99% 資料完整率、全市場掃描速度、排名速度及全天可用性仍待實測。

## 正式資料覆蓋率抽樣

2026-11-24 台灣時間的既有正式回補排程，針對 80 檔個股、2021–2025 年的 EPS、ROE 及現金股利支出抽查 1,200 欄位，取得 219 欄位，抽樣覆蓋率 18.25%。當時稽核母體為 2,031 檔。這個結果的分母僅為該批與三個欄位，無法用來估計全市場、其他財務指標或行情的完整率。抽樣也記錄到 TPEx 讀取逾時。

[正式回補排程紀錄](https://github.com/lungDa/Stock-research-robot/actions/runs/45309538143)

## 後續驗收

- 現有月線回補只排四個月。逆勢功能需要可驗證的 1、3、5 年台股還原歷史、五個基準的歷史價格、台美交易日曆與時點財報。
- 完成資料取得後，還需接入市場排名、調參與個人開關、60 分鐘監控、LINE 去重通知和進出場訊號。
- 回測核心尚無歷史訊號產生流程或平台入口。交易稅、手續費、滑價與流動性未計入。

## 部署與回滾

經審查批准後，先在測試環境確認 `/health`、`/ready`、網頁載入及台股備援行情寫入，再進行正式部署。使用既有資料表，無須結構遷移。若部署後出現回歸，重新部署上一版程式，並透過回滾 PR 撤回本階段提交。快取文件沿用原有格式。
